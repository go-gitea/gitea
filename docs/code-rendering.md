# Code highlighting and the diff viewer

This document describes how code and diffs are rendered. Both are rendered by the frontend,
the backend only provides data.

## Highlighting

All code is highlighted in the browser with [shiki](https://shiki.style/) (`web_src/js/modules/highlight/`).

- The backend detects the language (`modules/highlight`): the `[highlight.mapping]` setting, then the
  `linguist-language` git attribute, then the file name and content. It sends the linguist language name
  together with the plain, HTML-escaped code.
- `highlight.ts` maps the language name to a shiki grammar, loads the grammar on demand and returns the
  tokens of each line. The shiki theme maps TextMate scopes to the `tok-*` classes of
  `web_src/css/modules/highlight.css`, so colors come from the Gitea theme variables. The CodeMirror
  editor uses the same classes.
- `dom.ts` highlights server-rendered code in place (file view, blame, code search, code previews and
  code blocks of rendered markup). It wraps tokens around the existing text nodes, so markup inside
  the code like unicode escapes and search matches is kept. Templates opt in with
  `data-global-init="initCodeHighlight"` and `data-highlight-language`.
- The language table `shiki-languages.ts` is generated by `make generate-shiki-languages`.

Code is always highlighted as a whole document where one is available, because content outside of the
shown lines changes the result (multi-line comments and strings). Code is shown plain until its grammar
and content have loaded and is highlighted once; it never changes after that. Only places which have
no whole file (search results, code previews, diff excerpts in conversations, the editor's diff preview,
LFS diffs and files beyond `MAX_DIFF_VIEW_FILE_SIZE`) highlight the lines they have.

Consumers without JavaScript (API responses, emails, feeds) get unhighlighted code.

## Diff viewer

The diff pages (pull request files, commits, wiki commits, compare) share one viewer in
`web_src/js/modules/diffviewer/`. The page contains the file tree and a config (`diffViewerConfig` in
`routers/web/repo/diff_viewer.go`), the diff itself is streamed.

### Backend

- The stream endpoints (`.../diff/stream`, `.../diff/stream/compare/*`, `.../pulls/{index}/files/stream`)
  run `git diff` and write one JSON line per file (`services/gitdiff/diff_stream.go`): names, type, modes,
  language, flags (binary, vendored, generated, protected), LFS and submodule data, and the hunks as
  unified diff text decoded to UTF-8. A last line tells whether the diff was truncated.
- `MAX_DIFF_VIEW_SIZE` bounds the whole stream, `MAX_DIFF_VIEW_FILE_SIZE` a single file. Files beyond
  the per-file limit are sent without hunks and loaded on demand with `full=true&files=...`.
- Code comments of a pull request are a separate JSON endpoint (`pull_files_comments.go`), their
  Markdown is rendered and sanitized by the backend.
- Diff excerpts outside of the diff pages (conversation, editor preview) are emitted by
  `RenderDiffSnippet` as a patch text and rendered by `snippet.ts`.

### Frontend

| File | Responsibility |
| --- | --- |
| `stream.ts`, `parse.ts` | read the stream, parse hunks |
| `entry.ts` | `DiffFile`: one file and the data derived from its hunks, with explicit invalidation |
| `content.ts` | load the files of both commits (highlighting, context expansion), LFS objects, single large files |
| `render.ts`, `filebox.ts` | build the rows of a file's table and its header as HTML strings |
| `virtuallist.ts` | generic window-scrolling virtual list, only files near the viewport are mounted |
| `expand.ts`, `linediff.ts`, `worddiff.ts`, `escape.ts` | context expansion, line diff of LFS content, changed words, unicode escaping |
| `rendered.ts`, `csvdiff.ts` | image and CSV views |
| `comments.ts`, `comment-element.ts` | review threads and comment forms, they use the viewer only through `CommentsHost` |
| `viewer.ts` | orchestration |

Rules for changes:

- All HTML is built with the `html` tagged template, which escapes its values.
- A file is one table. Its element is built once and kept while scrolled out, re-highlighting updates
  the changed lines in place.
- Each module has unit tests next to it, the pages are covered by `tests/e2e/pr-diff-*.test.ts`.
